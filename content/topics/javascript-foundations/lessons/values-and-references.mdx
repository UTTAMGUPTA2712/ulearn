"Why did changing this object change that one too?" is the single most common
JavaScript bug in application code. The answer is always the same: some values
are copied, and some are shared.

## Two kinds of values

**Primitives** are copied: `string`, `number`, `boolean`, `null`, `undefined`,
`symbol`, `bigint`.

```js
let a = 5;
let b = a;
b = 10;

a; // 5 — untouched
```

**Objects** are shared: `{}`, `[]`, functions, `Map`, `Set`, `Date`, class
instances. A variable holds a *reference* to the object, not the object itself.

```js
const a = { count: 5 };
const b = a;
b.count = 10;

a.count; // 10 — same object
```

`a` and `b` are two labels on one thing. There is no copy anywhere.

## Equality follows the same split

```js
"abc" === "abc"; // true  — same value
{ id: 1 } === { id: 1 }; // false — two different objects
[1, 2] === [1, 2]; // false
```

Two objects are equal only if they are literally the same object. This is why
`useEffect(() => {...}, [someObject])` re-runs on every render if you build
`someObject` inline — a fresh object is a different reference every time.

## `const` does not mean immutable

`const` prevents *reassignment* of the binding. It says nothing about the
contents.

```js
const user = { name: "Uttam" };
user.name = "Gupta"; // fine — mutating the object
user = { name: "Gupta" }; // TypeError — reassigning the binding
```

If you want real immutability, you need `Object.freeze` (shallow) or a
discipline of never mutating.

## Function arguments are pass-by-value — of the reference

```js
function rename(user) {
  user.name = "Changed"; // mutates the caller's object
}

function replace(user) {
  user = { name: "Changed" }; // rebinds the local parameter only
}

const person = { name: "Uttam" };

rename(person);
person.name; // "Changed"

replace(person);
person.name; // "Changed" — replace() did nothing to the caller
```

The parameter is a fresh variable holding the same reference. Mutating what it
points at is visible outside; pointing it somewhere else is not.

## Copying properly

A shallow copy duplicates the top level only:

```js
const original = { name: "Uttam", tags: ["js", "react"] };

const shallow = { ...original };
shallow.name = "Gupta"; // original.name unchanged ✅
shallow.tags.push("css"); // original.tags ALSO changed ❌
```

`shallow.tags` and `original.tags` are still the same array. For nested data you
need a deep copy:

```js
// Modern, built in, handles Map/Set/Date/cycles:
const deep = structuredClone(original);

// Older approach — silently drops functions, undefined, Dates become strings:
const risky = JSON.parse(JSON.stringify(original));
```

For arrays, the copying operations are `slice()`, `[...arr]`,
`Array.from(arr)`, and the newer non-mutating methods `toSorted()`,
`toReversed()`, `toSpliced()` and `with()`.

Know which array methods mutate in place — this is the practical version of the
whole lesson:

| Mutates              | Returns a new array                  |
| -------------------- | ------------------------------------ |
| `push`, `pop`        | `concat`, `slice`                    |
| `shift`, `unshift`   | `map`, `filter`, `flatMap`           |
| `splice`             | `toSpliced`, `with`                  |
| `sort`, `reverse`    | `toSorted`, `toReversed`             |

## What to remember

- Primitives copy; objects and arrays share.
- Object equality is reference identity, never contents.
- `const` freezes the binding, not the value.
- Spread and `slice` are shallow — use `structuredClone` for nested data.
- When state feels "haunted", look for two names pointing at one object.
