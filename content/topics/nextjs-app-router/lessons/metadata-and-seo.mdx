Next.js generates your `<head>` for you. You describe the page; the framework
emits the tags, dedupes them across nested layouts, and handles the awkward
parts like absolute URLs for Open Graph.

## Static metadata

Export a `metadata` object from any `layout.tsx` or `page.tsx`:

```tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "Topics",
  description: "Browse every topic on ulearn.",
};
```

Metadata merges down the tree. A `title.template` in the root layout gives every
child page a suffix without repeating it:

```tsx
// app/layout.tsx
export const metadata: Metadata = {
  title: {
    default: "ulearn — learn it once",
    template: "%s · ulearn",
  },
};
```

Now the page above renders `Topics · ulearn`, and the homepage — which uses
`default` — renders the full string.

## Set `metadataBase` once

Open Graph and canonical tags require absolute URLs. Setting `metadataBase` in
the root layout lets every page below use relative paths:

```tsx
export const metadata: Metadata = {
  metadataBase: new URL("https://ulearn.dev"),
  alternates: { canonical: "/" },
};
```

Skipping this is a build error the first time you use a relative OG image, so
it is worth doing on day one.

## Dynamic metadata

For pages whose title depends on data, export `generateMetadata` instead. It
receives the same `params` Promise as the page:

```tsx
export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>;
}): Promise<Metadata> {
  const { slug } = await params;
  const post = await getPost(slug);

  return {
    title: post.title,
    description: post.description,
    alternates: { canonical: `/blog/${slug}` },
    openGraph: {
      type: "article",
      publishedTime: post.date,
    },
  };
}
```

If the page fetches the same data, wrap the fetch in React's `cache()` so it
runs once rather than twice:

```ts
import { cache } from "react";

export const getPost = cache(async (slug: string) => { /* ... */ });
```

## Canonical URLs

Every indexable page should declare one canonical URL. Without it, the same
lesson reachable via `?ref=twitter`, a trailing slash and an uppercase path
looks like three competing pages to a crawler.

```tsx
alternates: { canonical: "/topics/javascript-foundations" }
```

Relative is fine — `metadataBase` makes it absolute.

## File conventions do the rest

Four filenames in `app/` produce the remaining SEO surface:

- `icon.svg` / `apple-icon.tsx` — favicons and home-screen icons
- `opengraph-image.tsx` — the social preview card
- `sitemap.ts` — returns an array of `{ url, lastModified, priority }`
- `robots.ts` — returns crawl rules plus a pointer to the sitemap

`opengraph-image.tsx` is the interesting one. It renders JSX to a PNG at build
time using `ImageResponse`:

```tsx
import { ImageResponse } from "next/og";

export const size = { width: 1200, height: 630 };
export const contentType = "image/png";

export default async function Image() {
  return new ImageResponse(
    <div style={{ display: "flex", fontSize: 64 }}>ulearn</div>,
    { ...size },
  );
}
```

Only flexbox and a subset of CSS work — no CSS grid, no external stylesheets.
Every element with more than one child needs an explicit `display: "flex"`.

## Structured data

Metadata gets you the preview card. JSON-LD gets you rich results. There is no
special API — just render a script tag from a Server Component:

```tsx
<script
  type="application/ld+json"
  dangerouslySetInnerHTML={{ __html: JSON.stringify(schema) }}
/>
```

Useful schema types for a learning site: `Course` and `LearningResource` for
lessons, `BreadcrumbList` for navigation, and `WebSite` with a `SearchAction`
on the homepage.

## What to remember

- `metadata` for static pages, `generateMetadata` for data-driven ones.
- Set `metadataBase` and a `title.template` in the root layout, once.
- Declare a canonical URL on every indexable page.
- `sitemap.ts`, `robots.ts` and `opengraph-image.tsx` are code, not static files.
- JSON-LD is just a script tag you render yourself.
